# Kotis failure, connections and ICM audit — 2026-11-12

> Historical incident report. The later [reliability followup](2026-11-12-reliability-followup.md) records which remaining issues were repaired. These dated findings are not the current rules or feature specification.

## Finding

The reported explanation, “Kotis is too new; EDHREC hasn't indexed him,” is not
supported by the reproduction. At audit time Kotis has an EDHREC page and JSON
recommendations. Scryfall resolves **Kotis, the Fangkeeper**, released 2025-04-11,
with B/G/U identity. The original staples command fails with:

```text
Fetching EDHREC data for 'kotis-the-fangkeeper'...
Error: No NEXT_DATA found for commander 'kotis-the-fangkeeper'
```

The page returns HTTP 200, includes Next App Router payloads, and lacks the
`__NEXT_DATA__` script required by the old regex. Meren's established commander
page also lacks that script. This is a general parser incompatibility, not evidence
of a new-card indexing delay. The starter generator duplicates the same parser
and fails before its Scryfall color-identity fallback can run. Without Drew's
original command, environment and full transcript, this audit cannot prove the
exact historical sequence; it does establish a reproducible defect in this clone.

Sources: [Kotis on EDHREC](https://edhrec.com/commanders/kotis-the-fangkeeper),
[EDHREC JSON](https://json.edhrec.com/pages/commanders/kotis-the-fangkeeper.json),
[Scryfall card record](https://api.scryfall.com/cards/named?exact=Kotis%2C%20the%20Fangkeeper).

## Remaining risks and work

1. **Total budget is not a generator constraint.** Legacy `--budget 200` filters
   individual cards at $200 each. This is now clearly documented. The audit draft
   has 96 cards and a **$291.98 known subtotal**, with 28 unpriced card copies,
   so it fails a $200 validation. A future budget optimizer must allocate the
   total across commander, land base and packages; it must define unknown-price
   handling and preferred printings. This audit does not call that problem solved.
2. **Bracket/reference freshness.** `game-changers.md` says April 2025; the current
   Wizards [Commander overview](https://magic.wizards.com/en/formats/commander)
   and [February 9, 2026 update](https://magic.wizards.com/en/news/announcements/commander-brackets-beta-update-february-9-2026)
   postdate it. Static bracket rules and hand-maintained card sets are screening
   heuristics, not current comprehensive certification. Official-source refresh
   and rules-specific fixtures remain a separate repair.
3. **Combo completeness and cost.** Full-deck Spellbook checking enumerates pairs,
   triples and quadruples of candidate cards, uses truncated search pages and
   suppresses some HTTP failures. A database outage or an unsearched page can
   therefore be mistaken for no known combo. Do not promote a clean combo claim
   from it. Prefer a bounded provider deck-search integration with explicit
   incomplete status in the next pass.
4. **Heuristic roles and strategy.** Oracle-text classification can misclassify
   indirect effects; the generic fallback is not commander-specific synergy.
   Four win-condition slots remain deliberately unfilled in the Kotis draft.
5. **Optional discovery/browser cache.** The legacy top-commander refresher still
   uses Playwright/CSS selectors and was not browser-executed in this audit. Cache
   snapshots are historical; their absence or age must not be used as card legality
   or existence evidence. Other Ideation transformations were live spot-checked:
   419 tags, 32 graveyard color options, Golgari commanders and 138 Kotis tags.
6. **Supported commander combinations.** The generator is a single-commander tool;
   partner/background/special commander eligibility require separate review.
7. **Other maintenance debt.** Target-ratio logic is still duplicated between
   generator and ratio calculator; some older fetchers keep independent Scryfall
   clients. Goldfish/statistical accuracy, exhaustive deck-parser compatibility,
   third-party source ranking and all legacy JSON modes were not certified here.

## ICM cleanup and walk test

Form: three-stage pipeline feeding a deck record library. No directory rename is
needed to express its existing order. Historical deck artifacts stay in place.

| Old surface | Current home | Role / action |
|---|---|---|
| Long `CLAUDE.md` + overlapping root map | `AGENTS.md` router, `CLAUDE.md` pointer, `CONTEXT.md` workflow | Catalog/contract; retire duplicate routing payload. |
| Six HTML readers and duplicated pool schema | `_shared/data_sources.py` | Factory; one home for EDHREC and deck-pool behavior. |
| Implicit failure policy | `_shared/data-sources.md` | Contract; exact commands, errors, fallback and repair procedure. |
| Unwritten stage inputs/outputs/review gates | Stage `CONTEXT.md` contract headers | Contract; preserve useful local skill/reference routing. |
| New briefs assembled ad hoc | `_templates/brew-brief.md` | Factory template; explicit approval field. |
| No maintenance evidence surface | `_system/audits/` | Product; dated editable findings and generated evidence. |
| No reproducible safety checks | `tests/`, `.github/workflows/checks.yml` | Factory; offline tests plus manual live diagnostic artifact. |
| Historical brews/sessions/caches | Existing paths | Product; inventoried, not moved or deleted. |

The root router is under 60 lines. A cold agent reaches deckbuilding, optimization,
or provider recovery in one additional contract read. New-stage contracts name
input/output paths and a human check. New briefs have frontmatter; legacy artifacts
retain their historical formats, so approval is read from the actual record rather
than inferred from filenames. The generated inventory is rebuilt by script, not
hand-edited. Reference shelves and output records remain separate. No physical
file migration or speculative numbered-folder hierarchy was introduced.

## Verification and maintenance

Run from repository root:

```bash
python3 -m unittest discover -s tests -v
python3 _system/audit-connections.py --commander "Kotis, the Fangkeeper"
```

Tests cover parser schema drift, 404/outage/empty-pool fallback, Scryfall failure,
legality/identity filtering, 75-card batching, retries/timeouts, role edge cases,
brief overwrite protection, endpoint contracts, budget incompleteness, section
parsing and v3 board normalization. GitHub Actions runs the offline suite; its
manual live-check option stores connection evidence. Automatic fallback does not
edit source code. Repairs are reviewable changes with regression tests.
